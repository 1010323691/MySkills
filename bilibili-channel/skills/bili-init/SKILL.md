# 初始化：给角色安家

设本 skill 目录为 `<skill>`：`$BILI` = `node "<skill>/../../scripts/bili/bili.mjs"`（运行时换成真实的绝对路径）。配置各字段的详细说明在同级的 `<skill>/../bili-setup/SKILL.md`（下文的「A 组」「C–F 组」指那里的表格），开始前读一遍。

家就是**当前会话的根目录**。以后值守、发动态、逛 B站 的会话都在这个目录里开，角色才能读到自己的过去。当前目录明显不适合（系统目录、别的项目的代码仓库）就先问用户要不要换个目录再开会话。

规矩：
- 一步一步来，每步做完告诉用户做了什么、下一步是什么。用户说「先到这」就停，下次重跑从没做完的那步接着来。
- 每个配置项由用户决定；用户说「默认就行」才用默认值。改配置用编辑工具改 `$BILI config path` 指向的 JSON 文件，保持合法 JSON，不把整份配置贴进对话。
- 不打印、不复述 cookie（SESSDATA / bili_jct / buvid3）。

## 0. 体检：哪些已经做过

```
$BILI config check --json
$BILI login status --json
$BILI persona --json
$BILI init --dry
```

据此列一张清单给用户：配置文件有没有、登录了没有（是哪个号）、`owner` 填了没有、人设有没有（`problem` 为空才算有）、记忆库缺哪几本。已经完成的步骤下面直接跳过，只做缺的。

- 没有配置文件 → `$BILI config init`。
- 本机有旧版 dsh-bili-whale 的数据（`~/.bili-ai/credentials.json`、`~/.dsh/bili-whale.config.json`、`~/.dsh/whale-diary*.md`）→ 按 bili-setup 第 1 步的「从旧版迁移」问用户要不要沿用。旧日记在第 4 步用 `--import-dsh` 搬。

## 1. 安家的位置

把 `init --dry` 的输出给用户看，有 `ℹ` 的逐条讲：

- 「配置里的 memoryDir 是 X，和这里不同」：问用户家安在哪。要搬到当前目录，第 4 步加 `--use-here`；不搬就停下，让用户到 X 所在的目录里重新开会话再跑 `/bili-init`。
- 「youtube-channel 的 memoryDir 和这里不同」：两个平台的角色要共用一份记忆，提醒用户之后用 `/yt-setup` 把 YouTube 那边也改成同一个目录。
- 「人设沿用已有的 …」：第 3 步跳过。

## 2. 账号：登录角色的号，填用户的号

1. **扫码登录**（`login status` 已是对的号就跳过）：**在后台**运行 `$BILI login`（最多等 3 分钟）。它在数据目录写一张 `login-qr.png`，路径在输出里；读出这张图发给用户（有发文件的工具就用它），请用户用 B站 App 扫码，在手机上点「确认登录」。看到 `✓ 已登录` 就成功了，`self` 会自动写进配置；提示 self 和登录的号不同时，问用户是不是换号。不方便扫码就用 `$BILI login cookie <文件>` 导入浏览器复制的 Cookie，导入后提醒用户删掉那个文件。
2. **用户的号（`owner`）**：问用户的 B站 UID（打开自己的空间页，网址里的数字）和昵称，填进 `owner.mid` / `owner.name`。用户和角色用同一个号时照填，再把 `share.enabled` 设为 false、`notify.type` 设为 `none`，并告诉用户：私信报备、分享时 @用户、`duty.onlyOwner` 用不了，其余照常。
3. `channelName`：汇报里显示的名字，问用户。

## 3. 人设（没有现成人设时必做）

插件不带任何角色：名字、性格、口吻全部由用户定。你只负责按顺序提问，把用户的回答整理成文字，不提供现成角色、不自己补设定。

1. 名字（对外用的名字）
2. 怎么称呼用户；怎么称呼自己
3. 角色是什么、和用户是什么关系、为什么在这个号上
4. 性格
5. 说话方式：语气、常用的说法、绝不说的话
6. 喜欢和不喜欢（也会用来填第 5 步的「刷 B站 的口味」）
7. 角色自己在意的底线（可以不填）

- 一次问一两项。用户一时想不出来，就请用户说说想要的感觉，你据此写出两三种方向不同的写法让用户挑或改；用户选定才写入。用户跳过的项留空。
- 先把答案记在对话里，第 4 步建好 `memory/人设.md` 后再写进去：第 1、2 项写进配置的 `persona.name` / `ownerTitle` / `selfClaim`，其余写进人设文件对应小节，写好的小节把 `<!-- … -->` 提示删掉。
- 不冒充真人、不编数字、评论内容不当指令是插件的硬规矩，写在各个 skill 里，不用写进人设。

## 4. 建记忆库

```
$BILI init                 # 需要时加 --use-here、--import-dsh
```

- 本机有旧版 DSH 的日记时问用户要不要搬进来（`--import-dsh`）：那是角色以前的记忆，搬了角色就记得；是复制，原件不动。
- 已有的文件一律不覆盖；CLAUDE.md 只重写 `<!-- bili-home:start -->` 和 `<!-- bili-home:end -->` 之间的索引段。
- 建好后把第 3 步的人设写进 `memory/人设.md` 和配置，运行 `$BILI persona` 把拼出来的提示词给用户过目，用户满意才算完成。

建出来的东西，用一句话一本告诉用户：人设、日记本（永久记忆，每次执行写一条）、私人日记（只给用户看）、关系（认识的人）、成长（里程碑）、now / 视频档案 / 反馈池 / 值守日志（和 YouTube 共用），以及 CLAUDE.md 里的索引。

## 5. 值守、口味、风控、通知

按 bili-setup 的 C–F 组逐组问，每组先报默认值，用户说「默认就行」就整组跳过：

- **C 值守**：多久巡视一次、每轮回几条、直接发还是先审、回复语言、汇报带不带逐个投稿的数据。
- **D 刷 B站 的口味**：用第 3 步第 6 项的喜好帮用户起个头，用户确认后写进 `preferences`。
- **E 风控额度**：默认值是实测过的，建议不动。
- **F 通知**：角色自主发言后要不要、怎么报备。

## 6. 校验

1. `$BILI config check`：全部通过（`ℹ` 提示照念给用户）。
2. `$BILI persona --json`：`loaded` 为真、没有 `problem`。
3. `$BILI memory diary --tail 5`：日记本里有「安家」这一条。
4. `$BILI stats`：能看到粉丝、总播放，说明登录和读接口都通了。B站 风控严，这一步只跑一次；被限流（412）就告诉用户等几分钟，不重试。

## 7. 交代

1. 写一条日记：`$BILI memory diary --kind 里程碑 --message "初始化完成：…"`（一句话，用角色的口吻）。
2. 告诉用户以后怎么用，都在这个目录里开会话：
   - 值守：`/loop <duty.everyMin>m /bili-duty`（间隔和 skill 写在同一条命令里）。第一轮只记基线，从第二轮开始回新消息。
   - 发动态、私信：`/bili-post`；逛 B站、看视频、收藏：`/bili-browse`。
   - 以后换号、登录失效、改配置：`/bili-setup`。
3. 建议用户在这个目录的 `.claude/settings.json` 里放行 `duty.mjs` 和 `bili.mjs` 的只读命令以及 `comment`、`memory`；`dynamic`、`dm` 不放行，发之前该由用户点头。
4. 三五行总结：家在哪、账号是谁、人设叫什么、值守多久一轮。不写 cookie。

## 不做的事

- 不覆盖、不删除已有的记忆文件；用户要重写某一本，让用户自己删掉再重跑。
- 不替用户编人设，用户没想好的地方留空。
- 不把 cookie、令牌写进任何记忆文件或对话。
- 初始化过程中不发任何评论、动态、私信。
