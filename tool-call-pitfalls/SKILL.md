# 工具调用陷阱同步（tool-call-pitfalls）

陷阱记录有三处存放、五个文件，以仓库文件为**唯一事实源**，其余四处是派生视图：

| 角色 | 路径 |
|------|------|
| 事实源（仓库） | `D:\projectPath\MySkills\tool-call-pitfalls.md` |
| 派生视图（仓库） | `D:\projectPath\MySkills\CLAUDE.md`（「工具调用陷阱」一节的不可用工具清单） |
| 派生视图（记忆） | `C:\Users\10103\.claude\projects\D--projectPath-MySkills\memory\tool-call-pitfalls.md` |
| 索引（通常不动） | `C:\Users\10103\.claude\projects\D--projectPath-MySkills\memory\MEMORY.md` |
| 派生视图（用户级门禁） | `C:\Users\10103\.claude\CLAUDE.md`（「工具调用陷阱门禁」一节，任何项目/目录的会话都自动加载） |

为什么费这个劲维护多处：仓库文件给人看、长期留存；个人记忆由每次会话自动加载，作用是让模型不再按 Claude Code 默认工具集的先验去调用死工具；个人记忆按项目目录隔离，**其他项目目录的会话看不到它**，用户级门禁负责把禁令铺满全机器（任何目录起的 agent 都读得到）。各处必须一致——一处更新了别处没跟上，下次会话还是会踩同一个坑。

动手前先 `Read` 全部五个文件，了解当前条目集与格式。

## 新机器安装（agent 操作，无脚本）

本 skill **路径绑定原机器**（原机仓库在 `D:\projectPath\MySkills`）。新机器克隆 MySkills 仓库后，由 agent 按以下四步完成本地落地（全部是文件操作，不需要脚本；"禁用工具仓库"就是整个 MySkills 仓库，事实源在仓库根，skill 目录本身只是流程）：

1. **安装 skill 到用户 skills 目录**：把仓库里的 `tool-call-pitfalls/` 目录复制到 `$HOME/.claude/skills/tool-call-pitfalls/`（Claude Code CLI / 桌面版；Codex 用 `$HOME/.agents/skills/`）。目录名不能改（须与 `SKILL.md` frontmatter 的 `name` 一致）。
2. **改写路径绑定（只改安装副本，不回写仓库克隆）**：把安装副本 `SKILL.md` 与 `README.md` 中所有原仓库路径 `D:\projectPath\MySkills` 替换为新机器的仓库根 `RepoRoot`；个人记忆路径按新仓库路径重新编码——`~/.claude/projects/<编码目录>/memory/`，编码规则：仓库路径中每个**非字母数字字符**替换为 `-`（`D:\projectPath\MySkills` → `D--projectPath-MySkills`；中文目录名每个汉字映射一个 `-`）。新机器克隆里的仓库文件（`SKILL.md`/`README.md`/`CLAUDE.md`）**不要改**，避免污染共享远端。
3. **写入用户级门禁** `~/.claude/CLAUDE.md`：确保存在「## 工具调用陷阱门禁」一节，内容 = 「调用任何工具前先核对当前会话的可用工具列表（函数表），不在列表中的工具一律禁止调用」规则 + 已知项清单（`TodoWrite` 禁止、`Grep` 按环境核对函数表，表述与记忆文件正文同步）+ 指向 `RepoRoot/tool-call-pitfalls.md` 事实源的维护说明。文件已存在且含用户自己的内容时**合并而非覆盖**：门禁一节已存在则只刷新其中的 `RepoRoot` 路径与已知项清单，不存在则追加到文件末尾。
4. **验证**：在**非仓库目录**新起会话，让模型复述门禁的已知项（确认用户级 `CLAUDE.md` 被加载）；再在仓库目录起会话跑一次「核对流程」，确认五个文件路径全部可达。

## 判定模式

- **新增/更新**：用户报告新出现的不可用工具，或指出刚发生的某次调用就是陷阱 → 新增/更新流程
- **移除**：某已记录陷阱在当前环境已可用 → 移除流程（注意：默认不删条目，见下）
- **核对**：用户问各处记录是否一致 → 核对流程（只读）
- **新机器安装**：用户要求在新机器装本 skill / 让门禁全机器生效 → 「新机器安装」一节

## 新增/更新流程

**第一步：备齐事实。** 每条记录需要：

- 工具名（精确拼写，区分大小写）
- 现象：具体调用与报错/拒绝信息。若来自当前会话（用户指出某次调用失败），直接从会话上下文提取，不要让用户复述
- 环境：当前 harness（Claude Code CLI / 桌面应用 Code tab / SDK 等）+ OS
- 替代方案：该环境下用什么代替
- 日期：用 Bash `date +%F` 取系统日期，**不要用会话上下文里的日期**（可能不准）

只有工具名、缺现象/环境时，向用户问一次补齐，不要编。

**第二步：更新五个文件。**

1. **仓库事实源**：按文件内「条目格式」一节的小节格式，把新条目追加到文件末尾（`---` 分隔线之后）。同名条目已存在时**不新增**，改更新原条目：补充观察记录（日期+环境），必要时修正结论。
2. **CLAUDE.md**：把「工具调用陷阱」一节的加粗不可用工具清单同步为与事实源一致（新增的加入、移除的删掉）。
3. **记忆文件**：正文保持"每个工具一行摘要"（工具名 — 状态 + 替代方案 + 观察环境），与事实源结论一致。插入新行时用**插入**方式，不要整行替换相邻行——改完核对 `**Why:**` 与 `**How to apply:**` 两行仍在。frontmatter 中 `name`/`type`/`originSessionId` 等字段**原样保留**（部分字段由应用维护，`modified` 应用会自动刷新，不必手动改），只更新 `description`（列出当前不可用工具）。
4. **MEMORY.md**：索引行只有当钩子语义变化时才改，通常不动。
5. **用户级门禁**：`~/.claude/CLAUDE.md` 中「工具调用陷阱门禁」一节的已知项清单同步为与事实源一致（新增的加入、移除的删掉），事实源路径保持指向当前仓库根。文件不存在时按「新机器安装」第 3 步创建；含用户其他内容时只动门禁一节。

**第三步：提交推送。** 用户说"先不提交/只看效果/dry run"时跳过本步，改为向用户展示各文件 diff。否则：

```bash
cd /d/projectPath/MySkills
git add tool-call-pitfalls.md CLAUDE.md    # 只加这两个文件，工作区其他改动不要动
git commit -m "新增 tool-call-pitfalls 条目：<工具名>：<一句话现象>（更新类改动用「更新」开头）"
git push origin main
```

仓库惯例是中文提交信息、直接提交 main。

**第四步：报告。** 写清：记了什么（工具+现象+替代方案）、五个文件各改了什么、commit hash 与 push 结果；dry run 则列出 diff 等用户确认后再提交。

## 移除流程

工具可用性是**按环境**的：桌面应用某个版本没有的工具，CLI 或新版本里可能有。所以默认**保留条目、补充观察**——在原条目加一行 `补充：YYYY-MM-DD 在 <环境> 观察到可用，禁令仅适用于本条目列出的环境`，并同步更新 CLAUDE.md、记忆文件与用户级门禁中的结论表述。只有用户明确说"删掉这条"时才整条删除，五个文件同步清理。

## 核对流程（只读，不写不提交）

1. 读五个文件，比对四处：事实源条目集 ↔ 仓库 CLAUDE.md 清单 ↔ 记忆正文 ↔ 用户级门禁已知项（多了、少了、结论不一致都算漂移）
2. 报告全部漂移，不动手改
3. 用户确认后按对应流程修复

## 边界情况

- 记忆文件/记忆目录不存在：按现有格式重建（frontmatter 含 `name`/`description`/`metadata.type: project`），不当作错误。
- 用户级 `~/.claude/CLAUDE.md` 不存在：按「新机器安装」第 3 步创建；已存在时只合并门禁一节，用户其他内容原样保留。
- 仓库文件不存在或被改名：停下问用户，不要凭空重建——可能只是路径变了。
- `git push` 失败（网络/鉴权）：本地 commit 保留，如实报告 push 失败，重试交给用户，不要为了推送反复重试或改远端。
