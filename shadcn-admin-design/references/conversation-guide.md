# 需求访谈与对话链

不要一次抛出整张问卷。每轮通常 2–3 个相关问题，先复述已知答案，通过可用的问题工具或普通对话收集答案。选项给具体差异，并允许自由描述。异步提问后可继续只读分析和独立设计，但依赖问题未答前不要实施。

## 第一轮：目标与范围

- 是哪类业务，主要使用者是谁，最常完成什么任务？
- 需要哪些页面、关键操作和信息？先完成哪一页最有价值？
- 现有项目在哪里？先读取已提供路径或链接，没有提供才询问，不重复索取可访问材料。

按模式补问，相关问题可分到下一轮：

| 模式 | 必须澄清的差异 |
|---|---|
| 新设计 | 是否已有代码；导航结构；核心实体、指标与操作；首期包含和不包含的页面 |
| 优化 | 困扰的具体任务；必须保留的外观与行为；只改样式还是可调布局和交互；改善如何判断 |
| 重构 | 重构原因；只重做界面还是调整组件架构；路由、状态、接口、权限和业务行为的兼容边界；是否允许依赖或技术栈迁移 |

重构不自动意味着重写整站或换框架。只改组件结构而视觉不变时，先展示现状截图与保持视觉的目标预览，给迁移范围，仍获得实施确认。

## 第二轮：风格与主色调

1. 「你希望偏商务简洁、数据密集、轻盈现代，还是保留现有品牌？有喜欢或不喜欢的参考界面也可以说明。」
2. 「主色想用什么？可以给 HEX 或颜色名称；如果交给我建议，我会给具体色值和色板。」
3. 「浅色、深色还是都需要？更重视桌面信息密度，还是手机操作？」

把风格转为可实现的决定：密度、页面层级、字体和中文回退、圆角、边框、阴影、按钮强调方式、侧栏和导航。用户不确定时给 2–3 个可比较方向，不要求先学术语。

示例方向仅是建议，不是已批准：

- 商务简洁：蓝 #2563EB，中性背景，清晰边框，中等密度。
- 轻盈现代：青绿 #0F766E，较多留白，柔和卡片。
- 数据密集：靛蓝 #4F46E5，紧凑表格，明确对齐，精简装饰。

颜色名称要落实到色值；黑白或中性配色同样有效。按钮文字、焦点环、图表与侧栏选中态要有配套色板，不能只替换一个颜色。

## 第三轮：数据、交互与约束

先从仓库只读获取框架、组件、路由与包管理器，再问真正缺失的内容：

- 数据来自现有 API 还是本次仅做 UI？列表字段、筛选、批量操作、表单校验有哪些？
- 关键流程有哪些加载、空数据、失败、权限不足和保存反馈状态？破坏性操作如何交互？
- 有无品牌、语言、权限、浏览器、无障碍或交付时间约束？是否需要移动端、暗色、RTL？

仅问与范围有关的问题。无 API 时用符合业务含义的模拟数据并标明，接入范围写入简报。不要索取密钥做效果图。

## 对话示例

用户：「用这个技能。」→ 助手先给设计 / 优化 / 重构选项，等模式答案。

用户：「优化订单后台。」→ 询问痛点、范围和现状位置；只读查看项目。

用户：「列表太乱，只改列表。」→ 复述边界，再问风格、主色、主题，梳理字段与操作。

用户：「商务一点，蓝色，浅色，其他你定。」→ 建议具体蓝色色值，记录需求与假设；制作 V1 列表和必要状态截图，展示并请求确认。

用户：「颜色再淡一点。」→ 只改独立预览，展示 V2，仍不改目标代码。

用户：「确认 V2，开始改。」→ 记录确认，在批准范围内实现、验证，交付实际截图。
