# 效果图与确认

## 可评审的预览

预览是实施依据，要包含本次业务内容、配色和页面层级。优先在独立目录写可打开的 HTML/CSS 原型，用可用浏览器渲染截图。可用现有项目的只读截图作优化前对照，不能为截图先修改项目。

- 文字、表格、按钮和图表清晰可读，模拟数据贴近业务并标明。
- 在对话直接展示渲染图片，同时提供可查看原型链接或绝对路径文件链接；有应用预览工具时打开给用户看。
- 本地图片用绝对路径嵌入；只给路径或文字说明不能替代展示。
- 选图片生成时先遵守可用图片生成技能；注明概念稿，核对中文和组件可实现性。精确表格与交互优先代码渲染。
- 工具不足时说明具体限制，准备可打开原型，请用户查看后确认；不声称已有截图，不因工具失败跳过确认。

## 展示范围

按候选范围选代表性视图，避免无限扩展设计工作：

- 仪表盘：整体框架、指标、图表、业务入口。
- 列表：筛选 / 搜索、数据、分页与操作；范围涉及详情或编辑时补抽屉 / 弹窗。
- 表单：分组、校验、错误与提交反馈。
- 优化：能获取时展示同视口前后对照，解释痛点改善。
- 重构：视觉目标加迁移边界，明确保留与变化的行为。
- 涉及响应式时展示桌面与手机代表视口；明确要求双主题时分别展示。可参考 1440×900 和 390×844，按实际设备调整。

每版预览由代理实际查看，检查截断、溢出、中文回退、图表可读性、按钮位置和配色。未查看不能称为已验证。

## 版本与批准

预览命名 V1、V2 等，保留用户正在评审的版本。说明页面、状态、主色值、现状差异与技术边界。实施必须同时满足：

1. 用户已获得可查看的本次效果图或渲染预览。
2. 页面与关键业务范围明确，技术迁移没有隐藏在视觉方案里。
3. 用户明确批准对应版本实施，没有未解决的阻塞问题。

「选蓝色」「继续出图」「这个不错」「先看看」不满足第 3 条。「可以」如果是明确询问「按 V2 实现吗」之后的直接回答，可按上下文视为批准并记录，避免重复确认。

换主色、布局、页面或关键交互时更新预览并确认变更；已批准的无关部分可继续。符合既定设计的对齐修正等细节不用反复审批。

用户仅催促直接动工时，说明此技能按用户要求必须先预览确认，停在设计阶段，不能自行推定已撤销要求。用户明确表示撤销此前的效果图确认要求时，尊重最新指令，记录流程变化和实施范围。
