# 主 Agent 评论模板

主 Agent 发布处理报告、仅供参考处置记录、闭环状态评论或代发审核报告时读取。审核报告模板在 [reviewer-guide.md](reviewer-guide.md) 第 5 节。占位符必须换成真实记录；模板本身不是验证证据。正文**不要**包在代码块围栏里；代码标识符、路径、命令放进反引号，不裸写 `@xxx` 或 `#数字`。处理报告、处置记录、闭环状态评论不得含 `Reviewed-Head:`/`Verdict:` 开头的行（引用结论时写「结论为 CLEAR」），**首个非空行必须就是模板标题**（前面不加称呼或说明），`scripts/pr_state.py` 靠首行标题把它们与审核结论区分开。

## 逐项处理报告

```text
## 第 <k> 轮处理报告
PR：<URL>；当前完整 HEAD：<SHA>；对应审核评论：<链接>

### 处理状态
| 编号 | 原级别 | 状态 | 修复提交 / 反驳理由与证据 | 独立核销 / 裁决链接 |
|---|---|---|---|---|
| P1 | 必须修 | 已修复，待核销 | <提交 SHA + 改动说明> | 待复审 |
| P2 | 建议修 | 已反驳，待裁决 | <理由 + 证据> | 待复审（新起审核者） |
| P3 | 建议修 | 用户裁定：不修 | <用户原话与范围> | 待审核者记录 |
| P4 | 仅供参考 | 不采纳 | <一句理由> | 无须核销 |

验证：<实际命令、结果、对应 SHA；轻量验证的适用理由>
自检：<强度与结果 / 免自检及理由>
待复审范围：<上轮SHA..当前SHA；未关闭项；有无 base/范围变化>
复审方式：<续用上轮审核者 / 新起及原因，依据 SKILL.md 2.2>
```

没有独立核销前一律写「已修复，待核销」；提交反驳不等于关闭。此前未关闭的项全部保留在表中。仅供参考项写「已采纳（提交）」或「不采纳（理由）」即关闭。

## 仅供参考处置记录（CLEAR 后不产生新提交时）

```text
## 仅供参考处置记录
PR：<URL>；适用结论：<审核评论链接>（审核 SHA <SHA>）；当前完整 HEAD：<SHA>

| 编号 | 处置 | 说明 |
|---|---|---|
| P1 | 不采纳 | <一句理由> |
| P2 | 已采纳（gh pr edit） | <改了什么> |
```

## 闭环状态（限定模式停止、交接或用户越过门禁时）

```text
## 闭环状态
PR：<URL>；当前完整 HEAD：<SHA>；用户限定：<原话或「无」>
已满足门禁：<…>
缺失门禁：<如：当前 HEAD 无独立 CLEAR（P1 待核销）/ CI 未完成 / 合并命令被宿主拒绝>
恢复动作：<如：新起审核者对 <SHA> 复审 / 用户执行 `gh pr merge … --match-head-commit <SHA> …`>
用户决定：<用户明确越过门禁时记录原话；否则删去本行>
```

## 代发格式（审核者无法发布时）

主 Agent 校验 sha256 后，在审核者原始报告前只加一行，其余一字不改：

```text
> 代发：审核者 <标识> 原始报告，sha256 <值>，未改动
```

## 发布与恢复

正文写入 UTF-8 临时文件，明确 `--repo` 后用 `gh pr comment --body-file` 发布，避免 shell 对反引号、变量和多行文本二次解释。发布成功、记下 URL 后再删临时文件。超时或网络错误导致结果未知时，先读评论查重，不盲目重发。

## CLI 依据

- [gh pr create](https://cli.github.com/manual/gh_pr_create)：显式指定仓库、base/head 和正文文件。
- [gh pr checks](https://cli.github.com/manual/gh_pr_checks)：检查未注册时 `--watch` 会立即以非 0 退出；带 `--json` 时有失败检查也可能返回 0。等待与判定用 `scripts/pr_state.py --wait-ci`。
- [gh pr merge](https://cli.github.com/manual/gh_pr_merge)：`--match-head-commit` 与合并队列行为。合并队列/自动合并细节见 [merge-queue.md](merge-queue.md)。
