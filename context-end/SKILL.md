# 保存开发交接

遵守项目规则，确认项目根、当前工作线及交接目录，默认 docs/agent-context/。
按需读取 references/protocol.md 和 references/record-formats.md；正文模板在 assets/templates/。
不要把所有参考和模板一次性加载到上下文。

## 确定执行分支

- 无交接入口：只创建四个必需入口及本次实际有内容的记录，不预建空模块。
- 有旧文档：读取当前停止点和待更新资料，局部维护；复用现有设计书。
- 同一检查点重复执行：继续已有 session 草稿，避免重复条目。
- 无新的项目事实或工作状态：说明没有实质变更；不强造 session/决策/任务。
- 检测共享目录已有写入者：仅保存唯一 session 和待整合信息，遵守串行写入规则。

## 执行顺序

1. 对照本次要求、可见会话、已知开始基线、当前源码与真实命令结果，建立事实清单。标明本次修改、遗留改动和来源 unknown。
2. 采集分支/HEAD/worktree、暂存/未暂存/未跟踪、已提交变化及未完操作。只检查相关范围；基线未知就写 unknown。
3. 记录停止点、恢复入口、验收缺口、阻塞；先将已有 CURRENT 标为 partial，保留前一个可信停止点。
4. 按需更新模块、任务、正确命令、失败经验和长期决策。使用完整模板，缺信息写 unknown + 核实入口，不保留尖括号占位符。
5. 写 session。只有全局结构变化才改 PROJECT，只有导航变化才改 ROUTES/README；其他资料用 ID/路径引用。
6. 检查引用、状态、事实范围、保密和入口体量。可以运行 scripts/context_check.py 做只读结构检查；没有 Python 时用同等人工清单并说明未运行脚本。
7. 最后生成 CURRENT；保存已完整且已知未完项已记录时标 complete，否则保持 partial 并说明缺口。

## 约束

- 保存 complete 不代表开发完成、测试全部通过或全项目已探索。
- verified 必须有相符范围的真实验证；症状、推断和候选方案分别标注。
- 不把全量对话/diff/日志写进文档；长期信息去重、过大记录按领域拆分，保留索引。
- 保存前复核目标最新内容；并发冲突重读整合，不覆盖他人的状态。普通文件更新不承诺事务性。
- 不自动改业务代码、运行旧命令、提交推送、装依赖、改数据库、切分支、清理文件或管理后台服务。
- 不保存密钥和敏感数据；用户当前要求优先于交接中的旧建议。
- 不能保证感知窗口结束或在意外退出时自动保存；在用户触发/可执行检查点进行交接。

完成后简述更新路径、停止点、未完任务、保存完整性和实际持久化情况。落盘/检查失败时不能宣称交接成功。
