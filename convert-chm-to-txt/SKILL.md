# CHM 转常规 txt

## 执行顺序

1. 确认输入 .chm 路径与输出目录。用户未指定输出目录时，默认在 chm 同目录建 `<chm 文件名>_txt`。
2. 确认 7-Zip 可用（脚本靠它解包；缺失则先装）：
   ```bash
   "/c/Program Files/7-Zip/7z.exe" 2>/dev/null || winget install 7zip.7zip -e --silent --disable-interactivity
   ```
3. 先用 `7z l <chm>` 看一眼内部结构（顺便看体量：几百 MB 的超大包先告知用户再转），判断属于下面三种哪种，以便预期输出形态。
4. 运行脚本（自动识别结构，无需手工处理）：
   ```bash
   python <本skill目录>/scripts/convert_chm_to_txt.py "<chm 绝对路径>" "<输出目录>"
   ```
5. 转换后必做校验（终端多为 GBK 码页、直接打印中文必乱码，用 Python `ascii()`/`repr()` 输出）：
   - 阅读器式：`chapters/` 文件数 = page.js 章节表条数；无空文件；`全书.txt` 无 `<tag>` 残留、无 U+FFFD 替换字符。
   - HTML 式 / 纯文本式：抽查几个文件开头，确认中文正常、无混入 JS/CSS。
6. 向用户报告：识别出的结构、书名（如有）、章节/文件数、总字符数、输出目录结构。

## 结构与输出

| 内部结构 | 判断特征 | 输出 |
|---|---|---|
| 网页阅读器式（电子书最常见） | `js/page.js` 有 `pages[N]=['文件名','章节名',...]` 章节表 + `txt/` 章节文件 | `全书.txt`（按卷/章合并）、`目录.txt`、`chapters/` 每章一个、`images/` 封面 |
| 标准 HTML Help | 一批 `.htm/.html` 页面 | 保留原相对路径，每页一个 `.txt`（script/style 与标签已去除） |
| 纯文本打包 | `.txt` + 图片 | 重新编码 UTF-8（BOM），保留相对路径 |

所有输出文本为 `utf-8-sig`（带 BOM），Windows 记事本 / Word 双击即可正确显示中文。

## 异常分支与坑

- 阅读器式章节文件是 GBK 的 `document.write("HTML")` 脚本而非纯文本，不能直接复制使用。脚本按「有 document.write → 提取字符串参数；否则含 HTML 标签 → 解析；否则原样」的优先级自适应。
- 字符串提取假设文件内无转义反斜杠（此类文件已验证成立）。若遇到带 `\'` `\"` 转义的 CHM，把 `extract_write_payloads` 换成真正的 JS 字符串扫描器（识别反斜杠转义），不要直接按引号截取。
- 章节表正则 `pages\[\d+\]\s*=\s*\[` 只针对这类阅读器；`parse_pages` 另依赖每条以 `];`（分号）结尾来定位条目边界——分号缺失时会静默得到「章节: 0」或跨条目错切。换一本 CHM 若报「章节: 0」，先打开它的 js 看章节表实际写法（含分号），再调 `parse_pages`。
- 章节文件扩展名可能不是 `.txt`（脚本按 `.txt/.htm/.html` 收集磁盘文件）：js 中 `pages[N][0]` 须为去扩展名形式，与磁盘章节文件的去扩展名 stem 一致；若 js 写成带扩展名的文件名将无法匹配，该章记入「缺文件」并跳过。
- `7z l` 报 chm 结构无法识别或解包失败：先确认文件完整（大小、能否被其他工具打开），再报告用户，不要硬试。
- 临时校验脚本优先用 Write 工具落盘再执行，避免 Python 代码里的反斜杠被 shell / JSON 层吞掉（heredoc 会静默改代码语义）。
- 输出重名风险：同目录下不同子目录若有同名图片，`images/` 里保留了相对路径，不会互相覆盖。

## 约束

- 不修改源 .chm；解包走系统临时目录，脚本结束后自动清理。
- 用户只要合并文件或只要分章文件时，转换后按要求过滤输出，不要擅自另存。
- 图片只是随文件保留（封面/插图），不做 OCR、不做图文混排；用户有此类要求时先说明本 skill 不做，再单独处理。
