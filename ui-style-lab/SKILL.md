# 界面样式实验室

将用户给出的图片或设计要求转成可复用的组件代码，并持续积累到本地样式库。默认使用原生 HTML/CSS；交互需要时添加少量原生 JavaScript，用户指定技术栈时按其要求提供对应实现，并保留静态预览。

## 必须完成的交付流程

用户使用 `$ui-style-lab` 并提供样式图片，即表示要求执行以下完整流程。不要停在分析图片、给出建议或在回复里贴代码。

1. **查看参考图片，按样式生成代码。** 提取图片里的视觉特征，实际编写可复用的按钮或目标组件 HTML/CSS，并补充合理的交互状态。
2. **把生成代码保存到 skill 中。** 写入本 skill 的 `styles/<style-name>/`，包含组件 CSS、可独立打开的 `demo.html` 和 `notes.md`；原图可访问时一同保存。
3. **同步保存到仓库。** 将该样式同步到 MySkills 仓库的 `ui-style-lab/styles/<style-name>/`；skill 安装目录和仓库目录相同时只写一次。不能只保存在临时目录、其他业务项目或聊天回复中。
4. **更新展示页。** 将样式收录到 `gallery/index.html`，并将展示页及其所需资源同步到仓库，保留以前收录的样式。检查 skill 与仓库中该样式文件的内容一致，链接可用。
5. **返回展示页，让用户确认。** 打开可用的展示页，并在最终回复中提供可点击的总展示页和该样式的独立预览链接，明确询问“请确认展示效果是否符合参考图片；需要调整的地方可以直接告诉我。”保存和展示完成后再请求效果确认，不提前要求用户批准实现步骤。

用户确认后保留这版；用户指出偏差时，修改同一款样式，重新保存、同步和展示，再请用户确认。只有用户明确要求另存版本时才新增目录。

## 保存与同步位置

**Skill 目录**：本次实际读取的 `SKILL.md` 所在目录，用其绝对路径定位，不依赖终端当前目录。

**仓库目录**：本机默认为 `/home/gao/桌面/projectPath/MySkills`，样式库位于其中的 `ui-style-lab/`。用户明确指定其他 MySkills 仓库路径时使用指定路径。换机器且默认路径不存在时，先从当前工作区定位实际仓库；仍无法定位则询问仓库位置，同时完成 skill 内的代码与展示页，不得宣称已经同步。

仓库与 skill 安装目录不同时，同步本次样式目录及对应展示页变更；已有其他样式或卡片时合并保留，不整目录覆盖或删除。用文件比较或哈希检查本次组件代码、demo 和说明一致，并核实两处展示页均收录该样式、引用各自存在的资源。仓库已有该样式时以用户正在修改的仓库版本为基础生成，再同步回 skill，避免用旧安装副本覆盖新代码。

这里的“同步到仓库”指保存到仓库工作区；不自动扩展为 Git 提交、推送或外网发布。若文件不可写或同步失败，明确给出已完成位置、未完成步骤及原因，不能把部分完成当作整个流程完成。

```text
ui-style-lab/
├── SKILL.md
├── agents/openai.yaml
├── gallery/
│   ├── index.html          # 总示例页，每种样式一张卡片
│   └── gallery.css         # 仅控制展示页布局，不包含组件样式
└── styles/
    └── <style-name>/       # 小写英文短横线命名，例如 glass-blue
        ├── button.css     # 可复用组件代码，其他组件可用 component.css
        ├── demo.html      # 可独立打开，引用同目录组件 CSS
        ├── notes.md       # 参考来源、设计参数、使用示例及近似项
        └── reference.*    # 有可访问原图文件时保存，非必需
```

已有 [gallery/index.html](gallery/index.html) 和 [基础按钮示例](styles/soft-blue/demo.html) 可作为增量维护起点。`soft-blue` 是无参考图片的初始示例，不代表用户提供的设计。

## 根据图片设计

先实际查看图片，再提取轮廓、尺寸比例、圆角、颜色或渐变、边框、阴影、文字与图标、所在背景。多张图片或多个组件时结合用户描述确定目标，只有无法判断时才询问。图片无法读取时请用户重新提供，不把猜测描述成观察结果。

优先通过 CSS 和必要的 SVG 还原效果。组件的主体必须是真实按钮或对应语义元素，不能把整张截图作为按钮背景冒充实现。已有清晰图标资源可以复用；仅在确实需要纹理等位图素材时考虑图像工具。没有给出参考图时，根据文字需求设计并注明原创。

只有图片明确展示的状态才称为“还原”；悬停、按下、键盘焦点、禁用等未展示状态可以合理补充，在 `notes.md` 标注推断。字体、尺寸或素材无法准确确定时，说明近似项，避免声称像素级一致。

## 保存与展示

- 新设计使用新的 `styles/<style-name>/` 目录；用户要求修改现有样式时在原目录更新。新增时保留其他样式和示例页卡片，避免同名覆盖。
- 使用有辨识度的组件类名（如 `.usl-glass-blue-button`），用 CSS 自定义属性集中存储颜色、尺寸、圆角与阴影。组件 CSS 不包含 `body`、通用 `button` 等影响宿主页面的全局选择器；页面布局写在 demo 内或独立页面 CSS 中。
- 按钮用 `<button type="button">`，真实禁用状态用 `disabled`，保留明显的 `:focus-visible`。图标按钮提供可访问名称；有动画时照顾 `prefers-reduced-motion`。
- `demo.html` 展示主要按钮及悬停、按下、焦点、禁用状态；用可操作按钮展示真实交互，必要时附明确标注的固定状态预览。样式需要特定底色时在 demo 中保留该环境。
- `notes.md` 记录参考来源（只记录实际有的文件或用户描述）、关键设计参数、可复制的 HTML 使用片段、需引入的 CSS，以及补充状态或近似实现。不声称能从图片中获取原始源码。
- 更新 `gallery/index.html`：新增标题、简短特点、指向 `demo.html` 的预览 iframe、单页预览链接，以及 CSS 和说明链接。iframe 隔离各组件的样式；设置有意义的 title 和足够高度，避免裁掉阴影或焦点环。
- 默认使用相对路径和本地资源，不依赖 CDN、在线字体、构建步骤或接口；不要用 `fetch` 加载索引，以保证双击 HTML（`file://`）也能展示。

## 检查与交付

检查页面的本地链接及资源路径，确认每张卡片指向真实文件。浏览器工具可用时查看实际页面，并检查桌面和窄屏布局、真实 hover/active/focus/disabled；参考图存在时对照视觉差异再调整。工具不可用时完成能做的静态检查，并明确尚未完成视觉验证。

用户需要预览时优先打开 `gallery/index.html`；浏览器不支持本地文件时可以在样式库根目录运行 `python3 -m http.server 8000 --bind 127.0.0.1`，再访问 `http://127.0.0.1:8000/gallery/`（端口占用时换用空闲端口）。不要将本地展示自动发布到外网。

交付时给出总示例页、单样式页面及可复用代码的文件链接，简要说明实现特点、实际验证情况和 skill／仓库保存位置。浏览器预览使用临时本地服务时，同时给出长期可用的 HTML 文件链接，不只返回临时 URL。最后明确请求用户确认视觉效果。用户继续发图或要求调整时沿用这套目录，并执行完整保存、同步、展示与确认流程。
