# 用 Codex 调 GPT 生图

Claude 不能直接生成位图。本机 ChatGPT 桌面版自带 Codex CLI，登录 ChatGPT 账号后它带有 `image_generation` 工具（GPT 图像模型）。做法是用 `codex exec` 非交互地开一个会话，只让它做一件事：调用生图工具出 1 张图；图片落在 Codex 的数据目录里，再按会话 id 找出来复制到目标位置。脚本已把这些步骤和踩过的坑封装好。

下文 `$S` 指本 skill 目录下的 `scripts/`（加载时给出的 Base directory 加 `/scripts`）。

## 先确认能用（每台机器做一次）

```bash
"$S/codex_image.sh" -n -o /tmp/check.png -t 测试    # 只演示：打印找到的 codex 和命令，不真的生成
<codex> login status                                # 应显示 Logged in using ChatGPT
<codex> features list | grep image_generation       # 应为 true；false 时 <codex> features enable image_generation
```

`<codex>` 用上面演示输出里的路径。脚本找 codex 的顺序是：环境变量 `CODEX_BIN` → `PATH` → ChatGPT 桌面版自带的 `/Applications/ChatGPT.app/Contents/Resources/codex-cli/CodexCLI.app/Contents/MacOS/codex`。macOS 上 `which codex` 常常找不到，但不代表没装。都没有时让用户装 ChatGPT 桌面版或 `npm i -g @openai/codex`，再 `codex login`（用 ChatGPT 账号登录）。

## 单张

```bash
"$S/codex_image.sh" -o 输出/封面.png -p 提示词/封面.txt [-s 1536x1024] [-q high] [-r 参考图.png]
"$S/codex_image.sh" -o 输出/图标.png -t "一个扁平风格的耳机图标，白底" -s 1024x1024
```

- 一张通常 1～3 分钟，偶尔 6～7 分钟：用后台命令运行，完成通知到了再看结果，不要轮询。
- 成功打印 `OK 名字 -> 路径 (耗时)`，失败打印 `FAIL …` 和模型最后的回复（退出码 1）。
- 看图：用 Read 工具打开 PNG 就能看到画面；交给用户时附上路径，宿主有发文件的工具就直接发。

## 写提示词

- 脚本会自动加一段开场白：「直接调用图像生成工具、恰好 1 张、尺寸与质量、不要写代码 / 跑命令 / 修改文件 / 先提问，完成后只回复『完成』」。原因是 codex 是编程 agent，不说清楚它常会先写代码、建文件或反问。所以提示词文件里只写画面本身。
- 写全、写具体：画面构成与布局、风格、配色（给色值更稳）、字体感觉、要出现的每一段文字。做 UI 效果图时把按钮名、表头、示例数据都写出来，模型会照着画，中文文字渲染可用。
- 尺寸：横版 `1536x1024`（默认），竖版 `1024x1536`，方图 `1024x1024`；更宽写「1792x1024 或最接近的超宽横版」。尺寸只是给模型的要求，实际像素可能略有出入（实测要 `1024x1024` 给了 `1254x1254`），需要精确尺寸时生成后自己缩放或裁切。
- 一份长文档里有很多页的提示词时（比如每页一个代码块），先用一个小脚本拆成 `名字.txt`，每个文件 = 全局风格说明 + 本页需求，再批量生成。

## 一组图保持风格一致：先定稿一张，再带参考图批量

1. 先单独生成最有代表性的一张（风格锚点），给用户看，改到认可再往下走。风格不对就批量生成，等于一次浪费一整批的时间和额度。实战中这一步被否了两次才定稿（卡片式 → 列表式 → 提高信息密度），定稿后其余 20 张一次通过。
2. 其余每张都带 `-r 锚点.png`，并在提示词里写清参考图怎么用，例如：「附图是同一产品已定稿的『书籍管理』页面：严格沿用附图的顶部导航、品牌标、配色、字体、圆角、按钮与标签样式，只是画面换成下面描述的页面，不要照搬附图的内容」。只写「参考附图」时，模型容易把附图的内容也照搬过来。
3. 锚点自己不要带参考图：批量时在它的提示词文件开头写 `@ref: none`，或者先单独生成它。

## 并发批量

提示词目录里每个 `名字.txt` 生成 `输出目录/名字.png`：

```bash
"$S/codex_batch.sh" -d 提示词目录 -o 输出目录 -j 3 [-r 锚点.png] [-s 1536x1024]
```

- 不要一张一张串行跑（用户明确要求过并发）：默认同时 3 张，实测最多 8 张同时跑也全部成功；每张是独立的 codex 会话，互不影响。张数多时 3～5 并发即可，再高主要是更快耗额度、也更容易碰到限流。
- 已有同名图片会跳过，所以失败后**原样重跑同一条命令**就只补失败的那几张；要重画某张用 `-f` 或先删掉它。
- 个别图片在提示词文件开头写指令行单独指定（优先于命令行参数）：`@size: 1024x1536`、`@quality: medium`、`@ref: 另一张.png`（相对提示词文件所在目录；写了就替换 `-r` 给的参考图，可写多行）、`@ref: none`（这张不用参考图）。
- 整批用后台命令运行，完成后汇报成功 / 失败张数与输出目录；用户问进度时看 `输出目录/_batch.log`。
- 通看全部：`python3 "$S/contact_sheet.py" 输出目录/_总览.png 输出目录/*.png`（需要 Pillow），一张总览图方便用户一次确认。

## 坑（都已在脚本里处理，改脚本时别改回去）

- **macOS 自带 bash 3.2 + `set -u`**：空数组写 `"${arr[@]}"` 会报 `unbound variable`，脚本统一写成 `${arr[@]+"${arr[@]}"}`。
- **`-i` 会贪婪地吃掉后面的参数**：参考图放在 `--json` 之前，最后的 `-`（从标准输入读提示词）前面必须隔着别的选项，否则 `-` 会被当成一张图片。
- **事件流里没有图片路径**：`--json` 输出只有 `thread_id`，图片在 `~/.codex/generated_images/<thread_id>/exec-*.png`（设置了 `CODEX_HOME` 时在它下面）。
- **只读沙箱 + 空的临时工作目录**：codex 碰不到你的项目文件；工作目录不在 git 仓库里，所以要 `--skip-git-repo-check`。
- **macOS 的 `xargs -I` 替换后每个参数限 255 字节**：长路径或中文名会失败，批量脚本改用 `xargs -n 1` 把名字追加在命令末尾。
- **失败先看「模型最后的回复」**：常见是它反问、说不能生成、或去写代码了。收紧提示词后重试即可。完整日志在 `输出目录/.codex-image-logs/名字.{in,jsonl,err}`（`.in` 是实际发出的提示词）。
- **每张都消耗 ChatGPT 账号的额度**（每个会话都带着很长的上下文，大部分命中缓存）。几十张以上的批量先跟用户确认张数。

## 产出放哪

生成的图默认放在用户指定的位置；用户没指定、又是在代码仓库里做效果图时，放进不提交的目录（例如项目约定的 `design/`），不要混进要提交的源码目录。
